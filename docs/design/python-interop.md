# 設計メモ：Python との連携

状態：**検討中（実装しない）**

PopCorn は、Python で作った実行環境の上で動きます。連携には、向きが 2 つあります。

## 向き A：PopCorn から、Python のライブラリを呼ぶ

```
// 例（まだ書けません）
data >> Python("statistics.mean")
```

**崩れるもの**

* **安全性**：Playground では、共有された他人のコードを実行します。任意の Python を呼べると、`Fetch` と `WriteFile` 以外の外部効果（ファイル、OS、通信）を、PopCorn の約束の外へ持ち出せます。コマンドラインでは、任意のコード実行になります。
* **言語の約束**：非破壊、エラーの分類、「外部効果は、表に書いてある処理だけ」という約束が、保てなくなります。
* **型の対応**：`Num`（浮動小数点）、`Str`、`List`、`Dict`、`null`、`Bool` と、Python の `int`、`tuple`、`set`、`datetime` などの往復が、決まっていない。
* **単一ファイル完結**：非目標とぶつかります（どのライブラリを使うかが、環境に依存する）。
* **再現性**：ライブラリの有無とバージョンで、結果が変わる。ブラウザの Pyodide では、使えるパッケージが限られる。

**緩和の案**：ホスト（実行する側）が、**呼んでよい関数を、あらかじめ登録した一覧だけ**にする（許可リスト）。Playground では、一覧が空。コマンドラインでは、`--allow-python statistics.mean` のように、明示したものだけ。

## 向き B：Python から、PopCorn を呼ぶ（データ変換の DSL として組み込む）

```python
from popcorn_lang import run

result = run("@ >> Map { @ * 2 }", input=[1, 2, 3])   # [2.0, 4.0, 6.0]
```

* PopCorn の約束は、そのまま保たれます。呼ぶのが、Python（ホスト）の側だからです。
* 入力と出力は、JSON 互換の値（`None`、`bool`、`int`/`float`、`str`、`list`、`dict`）に限る。
* 外部効果は、ホストが選べる（`sandbox=True` なら、`Fetch`、`PostFetch`、`HttpRequest`、`ReadFile`、`WriteFile`、`Input`、`Env` を、使えなくする）。
* 実装は小さい：すでにある `parse_source` と `Evaluator` を、公開 API として整え、入力を最初の `@` にして、結果を Python の値へ変換するだけ。

**仕様に足す決まり**：ホストから入力を渡したとき、**プログラムの最初の `@` が、その入力になる**（渡さなければ、これまでどおり `null`）。

**決める必要があること**

* 同期版と非同期版（`run` と `run_async`）。
* 数値は、整数に見える値を、`int` で返すか、`float` のままにするか（PopCorn は、`Num` が 1 種類）。
* エラーは、`PopCornError` として、分類つきで投げる。
* コンパイル済みの形（`compile(source)` が関数を返す）を、足すか。

## 推奨

1. **向き B を先に、設計から実装へ進める。** 約束が崩れず、変更が小さく、Python の人が PopCorn を試す入口になる。
2. **向き A は、設計のままにする。** やるなら、許可リスト方式だけで、Playground では無効にする。
3. Playground の最初のサンプルに「Python との比較」を載せるのは、これらとは別に、いつでもできる（文章とサンプルだけ）。
